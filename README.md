Project One: Java Services and Software Testing

Overview

This repository contains my Project One work for my Computer Science program at Southern New Hampshire University (SNHU). The project includes three Java services: Contact Service, Task Service, and Appointment Service. I used Java, JUnit 5, and Eclipse to develop and test the services. Working on this project helped me understand the importance of following requirements, testing code, and finding errors before software is delivered to a customer.

1. How can I ensure that my code, program, or software is functional and secure?

I can help ensure that my code is functional and secure by following the requirements, checking for errors, and testing different situations. During Project One, I used JUnit 5 to test my Contact, Task, and Appointment services. For example, I tested whether the services rejected duplicate IDs, missing information, and invalid values. These tests helped me check whether the code behaved as expected. I also learned that passing tests does not automatically mean software is completely secure or free of bugs. I should continue testing after making changes, review my code, handle invalid input properly, and check for possible security problems.

2. How do I interpret user needs and incorporate them into a program?

I start by understanding what the customer needs the program to do and identifying the rules the software must follow. Then I turn those requirements into code and tests. In Project One, the Contact Service had requirements for contact IDs, names, phone numbers, and addresses. For example, a phone number had to contain exactly 10 digits. I used those requirements to write code that checked the information and JUnit tests to confirm that invalid phone numbers were rejected. This taught me that understanding the requirements before coding helps prevent mistakes and makes it more likely that the finished program will meet the customer's expectations.

3. How do I approach designing software?

When designing software, I start by reviewing the requirements and breaking the program into smaller parts. I try to make each class responsible for a specific purpose so the code is easier to understand, test, and update. In Project One, I worked with separate Contact, Task, and Appointment services. Each service handled its own type of information and operations. After writing the code, I tested the methods using JUnit 5 and fixed problems when they appeared. My approach is to start with a clear plan, build one part at a time, and test as I go. As I gain more programming experience, I want to improve my ability to design software that is reliable, easy to maintain, and secure.

I plan to use these skills in future computer science projects as I continue learning and developing my programming abilities.
